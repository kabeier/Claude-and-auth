diagrams/AU1-02-four-types.tldr

Walk left to right with ONE question each: "what goes with every request, and what does the server remember?"

  • Basic: your password on every request (base64 is not encryption: needs HTTPS). No real log out. Internal tools.
  • Session: log in once, get a cookie with a session id. Easy log out (delete the session), but the server looks it up on every request, which is hard with many servers. Server-rendered sites (Django, Rails).
  • Token (JWT): a signed note. The server just checks the signature: nothing to store, scales well. But you can't take it back before it expires.
  • Session + Token: the best of both. A short-lived access token (stateless, fast) plus a refresh token the server can revoke (real log out).

diagrams/AU1-03-jwt.tldr

"JWT, said 'jot'. Three parts, two dots."

  • Payload = claims about the user. sub is the user's id. Remember that name: in the database it becomes auth.uid().
  • Encoded, not encrypted: anyone can read it. So never put a password or card number in there.
  • Signature: anyone can READ a token; only Supabase can MAKE one that passes. Change one letter → 401.

We'll decode a real one in a few minutes.

diagrams/AU1-04-refresh.tldr

Two tokens, two jobs:

  • Access token (JWT, 1 hour): goes with every data request. The API only checks the signature, so it's fast.
  • Refresh token (long-lived): only used to get a new access token. Supabase keeps track of these, so log out can kill it.

"supabase-js does steps 1 to 5 for you, including refreshing a little before expiry. Maria never sees step 3."

Log out caveat (bonus card in the activity): an access token keeps working until it expires. That's why it's short.

diagrams/AU1-05-who-is-asking.tldr

"You never send a user id. You send a token, and Supabase reads the id out of it, signed so nobody can fake it."

  • apikey = which project. Same before and after log in.
  • Authorization: Bearer = which user. Friday: the publishable key → role anon. Now: the access token → role authenticated, and auth.uid() = the token's sub.

What you now know

  • Authentication (who? 401) comes before authorization (what? 403)
  • Supabase = Session + Token: a 1-hour access token (JWT) + a revocable refresh token
  • A JWT is readable by anyone, fakeable by no one
  • The token rides in Authorization: Bearer; Postgres sees it as auth.uid()
